# Экономичный запуск без истории чата

1. Читать инструкции/текущий PROGRESS/задачу/прошлые находки. Записать цель (ретест/фича/релиз), подтверждённые требования со ссылкой/датой, сборку/commit, origin, роль/id, конфигурацию. Не загружать весь портфель.
2. Проверить существующие тесты до переписывания: смысл, актуальность локаторов/контракта, независимость, последний реальный результат. Старый набор тестов сохранять: workflow с || true скрывает падения; serial после первого сбоя пропускает зависимости. Эти проблемы не доказывают дефект продукта.
3. Локально unit + discovery. Проверить стоимость сервисов, роли/сессии и согласовать слот данных. Окружение/ключ/почта/медиасервис заблокированы — отметить BLOCKED, продолжить доступное чтение кода.
4. MVP smoke: S-1 медиаконфигурация, H-1 запрет без продукта, «Вход» locked/password. Пропуск H-1 не даёт разрешения выпуска. Smoke не проверяет живое аудио/видео: отдельно два участника, слышимость, видео, join/leave и UI-старт.
5. Целевой регресс: M-9 старт без F5; M-4 постоянность; M-8 вкладка/presence; M-10 departure; M-6 модератор; M-7 settings; staff RBAC; M-5 запись отдельно. Расширять по диффу/риску, не гонять всё повторно без основания.
6. Мобильный риск обязателен: 320/360/375/390, 412/768/1024, portrait/landscape, touch=true,isMobile=true,DPR=3, PNG оригиналы; реальный tap и контрольный соседний элемент, overlay hit points. Брать существующий qa-kit/adaptive.mjs и tap helpers, не писать новый сканер. Уменьшение окна не является mobile evidence. Телефоны только по очереди.
7. Каждый красный: первый сбой/условия → ручная независимая попытка → сервер/сеть → классификация. 419 после stale XSRF, OTP timeout, 502 deploy и sandbox — окружение/данные до доказательства обратного. Новый договорённый контракт меняет тест с источником и сохраняет прошлый смысл в истории.
8. Каждому из 31 направлений дать применимость/проверено/не проверено с причиной; вести матрицу брендов/тем, продуктов/тарифов × админка деск/моб, ЛК деск/моб, оба приложения iOS/Android + DevTools. themes/* сверять отдельно при изменении ядра.
9. Cleanup + IDs + серверная сверка, отчёт MD/HTML через qa_report.py, черновики сообщений/комментариев, PROGRESS. HTML 1280/390 light/dark, 320 overflow, PNG original/lightbox/download. Заблокированный рендер не обходить.
10. Публикация только проверенных исходников без секретов; CI ненулевой при FAIL, артефакты через always(). Не переносить || true. Этот набор не добавлен в schedule CI: сначала подтвердить dedicated environment и безопасное восстановление.

Шаблон результата: requirement/source | case | build/role/config | PASS/FAIL/BLOCKED/SKIPPED | live/code/historical | evidence | cleanup | remaining risk. FAIL затем имеет классификацию, severity относится к доказанному пользовательскому последствию. Ручной повтор не превращает неизвестное ожидание в требование.
