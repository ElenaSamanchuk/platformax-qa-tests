# Telegram: автономная проверка только на чтение

Python 3.9+ и стандартная библиотека. Скрипт делает ровно два GET к Telegram Bot API: getMe и getWebhookInfo. Не отправляет сообщения, не вызывает getUpdates и не меняет webhook

Токен поступает только через STDIN, отдельного параметра с токеном нет. Передавайте его существующим безопасным механизмом через pipe; не вставляйте в командную строку, файлы проекта или историю shell. Шаблон аргументов потребителя STDIN:

```sh
python3 scripts/check_telegram_readonly.py --token-stdin \
  --expected-username fixture_bot \
  --expected-host fixture.test.nn99.ru \
  --output work/telegram-readonly.json
```

Этот пример без источника STDIN сам не является готовым сетевым запуском. Код завершения 0: обе API-пробы успешны, аккаунт является ботом с точным ожидаемым username, webhook использует HTTPS и точный ожидаемый host, pending_update_count равен 0. Код 1: проверка не пройдена, ошибка запроса либо вывода файла. Исторический last_error при пустой очереди сам по себе не приводит к FAIL

В JSON нет токена, полного URL webhook, имён/ID пользователей и исходных сообщений ошибок. Ошибка HTTP отражается только статусом; сетевые ошибки без URL и traceback

Проверка кода без сети и секретов:

```sh
python3 -m py_compile scripts/check_telegram_readonly.py scripts/test_check_telegram_readonly.py
python3 -m unittest discover -s scripts -p test_check_telegram_readonly.py -v
```

Offline-набор подменяет urllib-ответы: очередь 0 проходит даже с исторической ошибкой, очередь 1 завершается отрицательным результатом. Он также проверяет отсутствие секретного placeholder/пути webhook/сырого текста ошибки в JSON. Это тест логики скрипта, а не подтверждение живого бота или доставки сообщений

## Область и фактический результат

Источник: QA раздела Рассылки, родительская задача GF-6246, 29.10.2026. Это отдельная диагностика Telegram Bot API, а не полный Playwright/UI набор рассылок. Команды выше выполняются из корня этого репозитория. Username `fixture_bot` и host `fixture.test.nn99.ru` явно вымышленные примеры: перед разрешённым сетевым запуском укажите подтверждённые значения своего тестового бота

Исходный живой запуск 29.10.2026: exit 1, 6 из 7 проверок успешны; непустая очередь обновлений (1) оставляет результат FAIL. Это наблюдение окружения, не самостоятельное доказательство ошибки продукта. Приватный результат и доступы в репозиторий не включены. Повторный сетевой запуск при переносе не выполнялся. Offline unit 2/2 и компиляция проверяются отдельно; они не подтверждают доставку сообщений, исправление webhook или готовность раздела к релизу
