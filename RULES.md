# Правила для любого клиента

1. Прочитать README, docs/REQUIREMENTS.md, docs/WORKFLOW.md и актуальный PROGRESS проекта. История чата не требуется. Локальные правила владельца стенда имеют приоритет.
2. Только подтверждённый тестовый origin. Только собственные QA-AT комнаты/ДЗ/привязки; Luna, чужие и #138 не трогать.
3. Общие учётки/данные — согласованный слот и атомарный mkdir-lock. Телефоны не нужны этому набору. Запуск медиа/записи не разрешает дополнительных расходов.
4. Не публиковать env/storageState/cookies/токены/trace с персональными данными. Playwright-артефакты остаются локально, перед передачей проверять/обезличивать.
5. Cleanup live — завершение + снятие публикации + серверная проверка; ДЗ — свой provision/cleanup adapter с журналом IDs до mutation и восстановлением структуры/архивированием по серверу. Сбой не подавлять, IDs сохранить. При crash восстановить вручную.
6. Падение классифицировать, не автоматически объявлять баг. Исторические PASS не переносить на новую сборку. Known-bug названия — идентификаторы регресса, не сегодняшние диагнозы.
7. Набор целевого регресса не заменяет независимое полное QA: все применимые виды, мобильная эмуляция с touch/DPR3, реальные телефоны, бренды/темы и DevTools имеют отдельный статус.
8. Человеческий отчёт: ожидание и источник → факт → последствия → доказательства → сборка/роль → ограничения. Сообщения разработчику — только черновики без поручения отправить.

9. Единый репозиторий: выбирать feature suite по задаче через README/index; расширения используют общие config/fixtures/helpers. План будущего базового регресса не обозначать реализованным покрытием. В каждом отчёте repo+точный commit+feature instructions+результаты именно этого набора.
